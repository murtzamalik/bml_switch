## Idempotency-Key

| Rule | Detail |
|------|--------|
| Required on | `POST /payment/ift`, `POST /payment/ibft`, `POST /account/open` |
| Format | UUID generated by mobile per logical attempt |
| Header | `Idempotency-Key: <uuid>` |
| Replay | Same key + same outcome within ~24h returns cached success body |

---

## Auth headers (reminder)

```
Authorization: Bearer <channel_access_token>
Content-Type: application/json
X-Correlation-Id: <optional-uuid>
Idempotency-Key: <uuid>   # money / open only
```

Customer token goes in JSON body as `strToken` (not in `Authorization`).
